# 侧边聊天

PI-Desktop 插件：停靠在右侧工作面板的独立聊天。

- 按项目隔离的多轮历史（存在插件私有数据目录）
- 普通文本仍走宿主 `agent.complete`；附件对话走独立、只读的宿主后台 Agent，插件拿不到模型密钥
- 自动跟随宿主当前会话，可选附带其 transcript 当上下文
- 可选：将最新有效回复放回主输入框（仅插入草稿，不自动发送）
- AI 回复以安全 Markdown 渲染；本地打包 marked / DOMPurify，不使用 CDN

0.1.15 保持声明的 PI-Desktop >=0.21.1-0 要求，保留离线附件内容提取，不新增权限。图片需视觉模型；Office 提取不等于完整页面渲染，也不含 OCR。

| 格式 | 提供给模型的内容 |
| --- | --- |
| PNG、JPG/JPEG、WebP、GIF | 原图通过官方图片附件发送 |
| TIF/TIFF | 支持的单页/多页 RGB、灰度或调色板 TIFF 转 PNG；不支持的变体明确拒绝 |
| Word：DOC/DOCX | 提取正文、表格为 UTF-8 文本 |
| Excel：XLS/XLSX | 提取工作表/表格及保存值；XLSX 另附公式源，不重新计算 |
| PowerPoint：PPT/PPTX | 提取幻灯片文字与备注 |
| TXT、Markdown、CSV/TSV、JSON、C/C++、CUDA（CU/CUH）等 | 解码文本原样提供，不执行源码 |

支持文件选择、拖放和在输入框 Ctrl+V 粘贴真实图片/文件；也可直接粘贴文档文字、JSON 或代码作为普通消息。路径/链接文字不会自动导入。附件加入待发列表后仍须点击发送。每次最多8个文件/转换页，单文件10 MB，每个侧聊原件与提取副本合计20 MB；提取文本每文件256,000字节、合并引用JSON上限384,000字节，超限拒绝、不截断。保留“带上会话”、仅草稿回填及其余主侧隔离。首次新增 `agent.extension` 仍需明确授权，已有授权不因本次扩大。

真实格式样本已验证提取结果和官方发送参数；安装版0.22.0 Runner/侧车契约、Chromium模拟粘贴另有回归，仍不能代替运行中宿主、系统剪贴板及真实模型验收。支持边界、官方依据和复现命令见 [附件说明](docs/attachments-0.1.10.zh-CN.md)。

项目历史不再列出非当前、无标题且无消息的空影子分仓；同名但有内容的历史显示各自项目键，不自动合并或删除。独立/旧版入口和当前空项目保留，存储及附件归属不变。原因、证据与修复边界见 [项目历史重复排查](docs/history-duplicates-0.1.15.zh-CN.md)。

## 安装

1. PI-Desktop → 插件 → **加载开发插件**
2. 选这个目录
3. 打开右侧工作面板，选 **侧边聊天**

命令面板：`Side Chat: Open`（独立窗口）。

## 权限

| 权限 | 用途 |
|---|---|
| `ui.view` / `ui.panel` | 停靠视图 / 独立窗口 |
| `models.list` | 列出已登录模型 |
| `agent.complete` | 旁路补全（密钥留在宿主） |
| `desktop.control` | 读取跟随会话的上下文，不发送提示 |
| `clipboard.write` | 复制回复 |
| `shell.openExternal` | 经宿主授权打开 Markdown 中的 HTTP(S) / mailto 外链 |
| `renderer.extension` | 在宿主 Renderer 中通过白名单草稿接口回填，不自动发送；已有草稿不传往插件进程 |
| `agent.extension` | 仅对独立附件会话启用 Read/Glob/Grep 和附件目录限制，不是 OS 沙箱 |

插件自己不联网。宿主限制：每 60 秒最多 8 次补全，超时 90 秒。

## 从 0.1.0 更新和 reload 验证

**升级到 0.1.3 新增 Renderer 授权。** 请在插件页重新“加载开发插件”并选择原目录，检查并确认 `renderer.extension`；这是宿主窗口内可信代码的高风险授权，不能通过热重载静默获得。从 0.1.0 升级时还需检查 `shell.openExternal`。未授权或主输入框不可写时，回填会报错，绝不退回自动发送。

1. **Markdown：**请模型返回标题、粗体、有序/嵌套列表、代码块、表格和链接。应看到对应排版；代码内容保留原样，外链由系统浏览器打开，复制按钮仍复制原 Markdown。原始 HTML 不执行，远程图片只显示替代文字。
2. **会话跟随与回填：**保持侧栏打开，在同项目两个主会话间切换。开启左下角上下文开关，询问该会话独有信息。点击发送旁的回填图标，最新有效 AI 回复应插入当前主输入框，保留原有草稿，且不启动任务；侧聊自己的输入草稿不变。若异步校验期间切换会话或修改主草稿，回填会被拒绝。独立窗口漏掉事件时约 2 秒内只读恢复跟随。
3. **底部布局：**模型选择固定在最底部操作栏，与左右按钮统一为 24px 高且文字垂直居中。宽度减小时先隐藏下拉箭头，再隐藏思考深度标记，最后才压缩模型名称；放宽时按逆序恢复。隐藏标记不改变已选思考档位或菜单选项。长名称省略显示，悬停可看全名；回填与发送间距、选模和发送行为不变。逐步缩放窗口，确认上述顺序且控件始终同栏居中。
4. **项目历史：**项目 A 发一条独有消息，切到项目 B 不应看到 A 的对话；再切回 A 应恢复。抽屉的“项目历史”可以按项目浏览。浏览非当前项目时只读，点击“返回当前项目”后继续发送。发送中切项目，晚到回复只留在原项目。reload 后再切换 A/B，记录仍应分别保留。
5. **独立会话：**抽屉下拉框固定提供“独立会话”入口，统一查看全部已保存的非项目侧聊，包括原“无项目”记录；继续复用原 `general` 存储键，不清空或拆分历史。两个非项目会话切换后应看到同一历史列表；即使另有工作区打开，也不能误归入该项目。项目条目和归属不变，“旧版历史（未归类）”不猜测合并。原有历史容量限制保持不变。

旧版历史没有项目来源，升级时原样备份为插件数据目录的 `conversations.v1.json`，并保留到“旧版历史（未归类）”，不会猜测归属或清空。新版 `conversations.json` 使用按项目分仓的 v2 格式；每项目仍最多 40 个对话、每对话 80 条消息。新增模型/会话/工作区调用均走官方 API，不读取宿主数据库或密钥。

开发回归：项目根运行 `node --test tests/side-chat.test.cjs tests/draft-bridge.test.mjs`；用 BrowserPreview 打开 `tests/ui.html` 可验证模拟主输入框回填和宽窄屏布局，不会调用真实模型。官方单次草稿插入上限为 32 KiB UTF-8，超限明确拒绝、不截断。
